## Credit Card Fraud Detection: Handling Class Imbalance with SMOTE

### 📌 Overview
This task tackles the classic **extreme class imbalance** problem using the Credit Card Fraud Detection dataset. It trains a Logistic Regression model before and after applying **SMOTE** (Synthetic Minority Over-sampling Technique), compares Precision/Recall/F1 in both cases, and explains why accuracy alone is a misleading metric on this kind of data.

---

### 🎯 Objectives
- Use the Credit Card Fraud Detection dataset (Kaggle)
- Check the class balance of the target variable and visualize it with a bar chart
- Apply a technique to address imbalance — **SMOTE**
- Retrain the model with the balanced approach and compare Precision/Recall/F1 before vs. after
- Explain in writing why accuracy would be misleading for this dataset

### 🗂️ Dataset
`creditcard.csv` — **284,807 rows × 31 columns**, no missing values. Features `V1`–`V28` are PCA-anonymized transaction components, plus `Time` and `Amount`. Target: `Class` (`0` = normal, `1` = fraud).

**Class balance:**

| Class | Count | Percentage |
|-------|:-----:|:----------:|
| 0 (Normal) | 284,315 | 99.83% |
| 1 (Fraud)  | 492 | 0.17% |

This is an **extremely imbalanced** dataset — fraud makes up less than 0.2% of all transactions.

### ⚙️ Workflow

1. **Import Libraries**
   `pandas`, `numpy`, `matplotlib`, `seaborn`, `sklearn` (split, scaling, logistic regression, metrics), and `imblearn.over_sampling.SMOTE`.

2. **Load & Inspect Data**
   Confirmed shape (284,807 × 31), dtypes, and zero missing values.

3. **Check & Visualize Class Balance**
   Printed raw counts and percentages, then plotted a `countplot` of `Class` (0 = Normal, 1 = Fraud).

4. **Define X / y**
   `X` = all columns except `Class`; `y` = `Class`.

5. **Train/Test Split**
   80/20 split with `stratify=y` (`random_state=42`) → **227,845 training samples**, **56,962 testing samples** — stratification ensures the tiny fraud class is still proportionally represented in both sets.

6. **Standard Scaling**
   Fit `StandardScaler` on `X_train` only, then applied it to both `X_train` and `X_test` — avoids data leakage from the test set into the scaling parameters.

7. **Model Before SMOTE**
   Trained a plain `LogisticRegression(max_iter=1000)` on the scaled, **imbalanced** training data and evaluated on the untouched test set.

8. **Apply SMOTE**
   Applied `SMOTE(random_state=42)` to the **scaled training data only** (never to the test set), synthetically generating new minority-class (fraud) samples until the classes were equal:

   | | Before SMOTE | After SMOTE |
   |---|:---:|:---:|
   | Class 0 (Normal) | 227,451 | 227,451 |
   | Class 1 (Fraud)  | 394 | 227,451 |

9. **Model After SMOTE**
   Trained a fresh `LogisticRegression(max_iter=1000)` on the SMOTE-balanced training data, then evaluated on the **same original, untouched, imbalanced test set** — this is important, since the test set must reflect real-world class proportions for the evaluation to be meaningful.

10. **Before vs. After Comparison**
    Combined both models' metrics into a comparison table and a grouped bar chart (Precision/Recall/F1).

11. **Written Explanation**
    Printed a plain-English explanation of why accuracy is misleading on this dataset.

**Before vs. After Comparison**

| Model | Accuracy | Precision | Recall | F1 Score |
|-------|:--------:|:---------:|:------:|:--------:|
| Before SMOTE | 99.91% | 82.67% | 63.27% | 71.68% |
| After SMOTE  | 97.41% | 5.78% | **91.84%** | 10.88% |


---

### 🔍 What This Comparison Actually Shows

This isn't a case where SMOTE made things unambiguously "better" — it's a **precision/recall trade-off, taken to an extreme**:

- **Recall jumped** from 63.27% → 91.84%: after SMOTE, the model catches far more actual fraud cases (90/98 instead of 62/98).
- **Precision collapsed** from 82.67% → 5.78%: the model now also flags huge numbers of normal transactions as fraud, because training on a 50/50 synthetic dataset taught it that fraud is common — which it isn't at prediction time.
- **F1-score got worse** (71.68% → 10.88%) because F1 balances precision and recall, and the precision collapse dominates.
- **Accuracy dropped** (99.91% → 97.41%) simply because there are now far more false positives among the 56,864 normal transactions, even though each individual false positive barely dents overall accuracy given how large that class is.

**Takeaway:** plain Logistic Regression with default 0.5 decision threshold, trained on fully-balanced 50/50 synthetic data, over-corrects — it starts assuming fraud is far more likely than it actually is. In practice this would need to be paired with **threshold tuning** (raising the classification threshold above 0.5 after training on SMOTE data) or a **lighter oversampling ratio** (e.g., `sampling_strategy=0.1` instead of full balance) to get the recall improvement without destroying precision. As implemented, SMOTE here demonstrates the concept correctly and produces a valid, leakage-free before/after comparison — it just also demonstrates a common real-world pitfall of naive full oversampling.

---

### ⚠️ Why Accuracy Is a Misleading Metric Here (In Writing)

The credit card fraud dataset is extremely imbalanced — only about 0.17% of transactions are fraudulent. A model that predicted "Normal" for every single transaction, without learning anything at all, would still score roughly 99.8% accuracy, while catching **zero** fraud cases. That's exactly what happened here in miniature: the "Before SMOTE" model reached 99.91% accuracy, but that number alone hides the fact it only caught 63% of actual fraud. Because the whole point of fraud detection is finding the rare fraudulent transactions, **precision, recall, and F1-score** — which specifically measure performance on the minority class — are far more informative than accuracy. Recall matters most of all here, since missing real fraud (a false negative) is typically far more costly to a business than occasionally flagging a normal transaction for review (a false positive).

### ✅ Summary
On this extremely imbalanced fraud dataset (99.83% normal vs. 0.17% fraud), the baseline Logistic Regression looked excellent on accuracy (99.91%) but only caught 63% of fraud. Applying SMOTE to fully balance the training data pushed recall up to 91.84% but caused precision to collapse to 5.78%, illustrating both the value of oversampling for catching more fraud and the risk of over-correcting without threshold tuning. The exercise makes the core lesson concrete: on imbalanced data, accuracy hides the metric that actually matters, and fixing class imbalance is a trade-off to be tuned, not a switch to flip.
